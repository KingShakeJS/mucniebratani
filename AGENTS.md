# Правила разработки монорепозитория «Социальная сеть»

## Инструменты

- Пакетный менеджер: строго `pnpm`. Использование `npm` или `yarn` запрещено.
- Workspaces описаны в `pnpm-workspace.yaml`: `client`, `server`, `shared`.
- Все зависимости устанавливаются только через `pnpm add` из корня или соответствующего пакета.

## Управление зависимостями

- Во всех файлах `package.json` (корень, `client`, `server`, `shared`) используются только строго фиксированные версии библиотек без префиксов диапазонов (`^`, `~`, `>=`, `*`).
- Неправильно: `"concurrently": "^10.0.7"` или `"zod": "~3.24.0"`.
- Правильно: `"concurrently": "10.0.7"` или `"zod": "3.24.0"`.
- Исключение: внутренние ссылки на пакеты монорепозитория (`"@social/shared": "workspace:*"`).
- При установке новых пакетов всегда использовать флаг `--save-exact` (или `-E`); в корне проекта включено `save-exact=true` в `.npmrc`.
- При обнаружении нефиксированных версий в существующих `package.json` немедленно исправлять их на точные.
- Проверять все блоки (`dependencies`, `devDependencies`, `peerDependencies`) во всех пакетах.

## TypeScript

- Везде включается `"strict": true`.
- Использование `any` запрещено. Для неизвестных данных используйте `unknown` с последующим сужением типа.
- Для читаемости сложных пересечений типов используется утилита:
  `type Prettify<T> = { [K in keyof T]: T[K] } & {};`
  Она расположена в `@social/shared` (`src/types/utils.ts`).

## Контракты API

- Все Zod-схемы и выведенные из них типы (`z.infer`) описываются только в пакете `@social/shared`.
- Схемы и типы переиспользуются и на бэкенде, и на фронтенде. Дублирование контрактов запрещено.
- Импорт контрактов: `import { registerSchema, type RegisterInput } from '@social/shared';`.

## Язык интерфейса

- Весь пользовательский интерфейс (заголовки, подписи полей, плейсхолдеры, кнопки, ссылки, уведомления, сообщения об ошибках валидации и ответы API для пользователя) должен быть строго на русском языке.
- Новые пользовательские тексты в `client`, сообщения валидации в `@social/shared` и ответы `server` добавлять только на русском языке.

## Фронтенд (`client`)

- Next.js App Router; роутинг Next.js живёт в `src/app`.
- Внутри `src/` соблюдается строгий Feature-Sliced Design со слоями:
  `app`, `pages`, `widgets`, `features`, `entities`, `shared`.
- Импорты идут только сверху вниз: `app → pages → widgets → features → entities → shared`.
- Импорты между слайсами запрещены. Каждый слайс имеет публичный API строго через `index.ts`;
  внешний код импортирует только из `index.ts` слайса, а не из其内部ных файлов.
- Внутренние модули слайса импортируются относительными путями.
- Слой `app` содержит провайдеры, роутинг и глобальную конфигурацию.

### Тема MUI

- Основной акцентный цвет проекта по умолчанию (`palette.primary.main` в теме MUI) — `#228B22`. Он задан константой `DEFAULT_PRIMARY_COLOR` в `client/src/app/providers/MuiProvider.tsx`; оттенки `light`, `dark` и `contrastText` вычисляет MUI автоматически. При создании или сбросе темы `primary.main` должен возвращаться к `#228B22`.

### Адаптивная вёрстка

- При разработке любого интерфейса сразу применять принцип Mobile-First и ступенчатую адаптивность по стандарту контейнеров Bootstrap 5:
  - `xxs`: `0px` (от `320px`, `<375px` — ширина контейнера `100%`);
  - `xs`: `375px` (`<576px` — ширина контейнера `100%`);
  - `sm`: `576px` (макс. ширина контейнера `540px`);
  - `md`: `768px` (макс. ширина контейнера `720px`);
  - `lg`: `992px` (макс. ширина контейнера `960px`);
  - `xl`: `1200px` (макс. ширина контейнера `1140px`);
  - `xxl`: `1400px` (макс. ширина контейнера `1320px`).
- Контейнеры должны иметь `width: 100%` и безопасные боковые отступы `px: { xxs: 1.5, sm: 3 }`; горизонтальный скролл на любых ширинах запрещён (`overflow-x: hidden` на `html`/`body`).
- Для ограничения ширины страниц и секций использовать компонент `<Container>` из `@mui/material` с подходящим `maxWidth` под задачу (например `xs` для форм авторизации, `xxl` для профиля, `md`/`lg` для ленты и основного контента).
- Для внутренней раскладки использовать адаптивные пропсы MUI (`sx={{ flexDirection: { xxs: 'column', md: 'row' } }}`, `Grid`, `Stack`); базовые мобильные стили задавать через `xxs`, так как `xs` начинается с `375px`.

## Бэкенд (`server`)

- Внутри `src/` используется слоистая структура:
  `config`, `models`, `controllers`, `services`, `routes`, `middlewares`, `sockets`, `utils`.
- `routes` только объявляют маршруты, `controllers` обрабатывают HTTP, `services` содержат бизнес-логику,
  `models` описывают схемы БД, `sockets` — Socket.io, `config` — конфигурацию окружения.

## Сеть

- Фронтенд обращается к бэкенду только через относительный путь `/api`.
- `next.config.ts` настраивает `rewrites`: `/api/:path*` → `http://localhost:5001/api/:path*`.
- Прокси исключает проблемы CORS и позволяет передавать `httpOnly` cookies.

## Документация API

- При создании или изменении любого нового API-эндпоинта на бэкенде обязательно обновлять его OpenAPI (`@openapi`) документацию для Swagger.

## Команды

- `pnpm dev` — одновременный запуск `server` и `client`.
- `pnpm --filter @social/server dev` — только бэкенд.
- `pnpm --filter @social/client dev` — только фронтенд.
- `pnpm typecheck` — проверка типов во всех пакетах.
